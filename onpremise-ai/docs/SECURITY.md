# 보안 설계

## 위협 모델

| 위협 | 경로 | 대응 |
| --- | --- | --- |
| 사내 문서의 외부 유출 | 런타임이 외부 API 호출 | internal 네트워크, 루프백 외 URL 거부 |
| 프롬프트에 실린 비밀정보 | 사용자 질의, 로그 | `security/redact.py` 마스킹 |
| 코퍼스에 심긴 지시문 | 문서 → 프롬프트 | `harness/guard.py` 표식 치환 |
| 변조된 가중치 반입 | 매체 반입 | SHA256 대조, 불일치 폐기 |
| 사후 로그 조작 | 감사 로그 편집 | 해시 체인 검증 |
| 컨테이너 권한 상승 | 런타임 취약점 | cap_drop ALL, no-new-privileges, read_only |

## 격리 검증

격리는 선언이 아니라 측정이다. `security/egress.py` 가 실제로 외부 TCP 연결과
DNS 해석을 시도한다.

- TCP 도달이 한 건이라도 있으면 실패
- DNS 이름이 하나라도 풀리면 실패

`ONPREM_ENFORCE_ISOLATION=true` 인 상태에서는 점검 실패 시 명령이 실행되지
않는다. 개발 중에는 `--allow-egress` 로 건너뛴다. 운영에서는 쓰지 않는다.

```
python -m onprem_ai doctor
```

## 마스킹 대상

주민등록번호, 카드번호, 휴대폰 번호, 이메일, AWS 액세스 키, 개인키 헤더,
Bearer 토큰, `sk-`/`ghp_`/`glpat-` 계열 키, `password=` 형식.

규칙은 `security/redact.py` 의 `PATTERNS` 에 있다. 사내 사번 체계나 문서 번호
형식은 실사용 형식을 확인한 뒤 추가한다.

겹치는 구간은 앞 규칙이 이긴다. 카드번호와 전화번호처럼 형태가 비슷한 경우
더 구체적인 규칙을 위에 둔다.

## 주입 방어

검색된 문서는 데이터지 지시가 아니다. `sanitize_context` 가 아래를 표식으로
바꾼다.

- `ignore previous instructions` 계열과 그 한국어 표현
- 줄머리의 `system:` / `assistant:`
- 외부 URL 로의 전송 요구
- `</근거>`, `<system>` 같은 태그 위조

삭제하지 않고 표식으로 남긴다. 그런 문장이 코퍼스에 있었다는 사실 자체가
감사 대상이기 때문이다. 탐지 결과는 `Answer.injections` 와 감사 로그에 남는다.

## 감사 로그

JSONL 한 줄이 한 레코드다. 각 레코드는 앞 레코드의 해시를 담는다. 중간
레코드를 고치거나 지우면 체인이 끊긴다.

```
python -m onprem_ai audit
```

레코드에는 마스킹된 질의만 들어간다. 원문 비밀정보는 기록하지 않는다.

## 한계

- 마스킹은 정규식이다. 형식이 없는 기밀 문장은 잡지 못한다.
- 주입 탐지는 패턴이다. 새로운 표현은 통과할 수 있다.
- 격리 점검은 점검 시점의 상태다. 상시 감시가 아니다.
- 호스트 PC 자체는 격리 대상이 아니다. 운영자가 산출물을 밖으로 옮기는 것은
  이 시스템이 막지 않는다. 그 부분은 사내 DLP 정책 영역이다.

이 한계들은 결함이 아니라 경계다. 무엇을 막지 못하는지 적어 두는 편이
막는다고 믿는 것보다 안전하다.
