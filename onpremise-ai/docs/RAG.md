# RAG 설계

## 왜 하이브리드인가

임베딩만 쓰면 사번, 장비 모델명, 규정 조항 번호처럼 정확 일치가 중요한 질의를
놓친다. BM25 만 쓰면 표현이 다른 같은 뜻을 놓친다. 둘 다 둔다.

## 결합 방식

RRF(Reciprocal Rank Fusion)를 쓴다.

```
score(d) = Σ 1 / (k + rank_i(d)),  k = 60
```

가중합을 쓰지 않는 이유는 코사인 유사도와 BM25 점수의 스케일이 서로 다르고
코퍼스마다 분포가 바뀌기 때문이다. 순위 기반 결합은 그 재조정을 없앤다.

두 검색기가 모두 상위로 올린 문서가 자연히 앞선다. `Hit.matched_by` 로
어느 쪽이 잡았는지 확인할 수 있다.

## 한국어 처리

형태소 분석기를 반입하지 않는다. 사전 파일이 늘면 반입 검증 대상이 늘고,
사내 용어는 어차피 사전에 없다.

대신 어절 토큰과 음절 바이그램을 함께 색인한다.

```
"망분리" → ["망분리", "망분", "분리"]
```

조사가 붙어 어절이 달라져도 바이그램이 겹쳐 부분 일치가 산다. ASCII 단어는
바이그램을 만들지 않는다. `BM25` 같은 토큰이 잘게 쪼개져 노이즈가 되는 것을
막기 위해서다.

## 청킹

기본값 700자, 겹침 120자.

- 문단 경계를 우선 지킨다.
- 문단이 목표보다 길면 문장 경계로 자른다.
- 문장도 길면 글자 단위로 자른다.
- 겹침 접두에 구분자를 포함시켜 청크 길이 상한을 `size + overlap` 으로 묶는다.

## 저장 형식

`var/index/vectors.jsonl` 과 `var/index/bm25.json` 두 파일이다. 파일이라
백업과 반출입 검증이 단순하다.

임베딩 모델을 바꾸면 벡터 차원이 달라진다. `VectorStore.add` 가 차원 불일치를
잡아 전체 재색인을 요구한다. 조용히 섞이는 것보다 낫다.

## 지원 입력

`.txt`, `.md`, `.rst`, `.csv`, `.json`, `.yaml` 을 읽는다.

PDF, DOCX, PPTX, HWP 는 거부하고 변환 방법을 안내한다. 바이너리 파서를 끌어오면
의존성과 공격 표면이 함께 늘기 때문이다. 변환은 반입 전 단계에서 한다.

## 성능 특성

현재 구현은 전체 스캔이다. 청크 N 개에 대해 질의당 O(N) 이다.

| 청크 수 | 예상 질의 지연 |
| --- | --- |
| 1천 | 수 ms |
| 1만 | 수십 ms |
| 10만 | 수백 ms, 재검토 필요 |

10만을 넘기면 근사 최근접 색인 도입을 검토한다. 그 전까지는 서비스를 늘리지
않는 편이 격리 관점에서 유리하다.
