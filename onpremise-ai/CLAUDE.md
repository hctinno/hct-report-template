# 온프레미스 AI 프로젝트 지침

## 목적

사내 PC 의 로컬 LLM 을 격리 환경에서 구동하고, 그 위에 RAG 와 하네스를 올린다.
개발·구축·테스트가 목적이다.

## 시작 순서

1. `README.md` 에서 구성과 명령을 확인한다.
2. `docs/ARCHITECTURE.md` 로 계층과 질의 흐름을 잡는다.
3. 손대는 영역의 문서를 읽는다. 보안은 `docs/SECURITY.md`, 검색은 `docs/RAG.md`,
   프롬프트·검증은 `docs/HARNESS.md`.

## 작업 방식

- 답변과 문서는 한국어로 작성한다. 기술 용어, 코드 식별자, 파일 경로, 명령어는
  원문을 유지한다.
- 서브에이전트를 실행할 때는 프롬프트에 "보고는 한국어로 작성한다"를 명시한다.
- 완료라고 말하기 전에 `scripts/run_tests.sh` 를 돌리고 결과를 제시한다.
  실패가 0 이 아니면 완료가 아니다.
- 동작을 바꾸면 테스트를 함께 바꾼다. 테스트 없는 동작 변경은 완료가 아니다.

## 어길 수 없는 규칙

- **서드파티 패키지를 추가하지 않는다.** 표준 라이브러리만 쓴다. 정말 필요하면
  먼저 사용자에게 이유와 대안을 제시하고 승인을 받는다.
- **루프백 밖 주소를 허용하지 않는다.** `config.ALLOWED_HOSTS` 를 넓히지 않는다.
- **`deploy/docker-compose.yml` 의 `internal: true` 를 지우지 않는다.** 격리가
  이 한 줄에 걸려 있다.
- **감사 로그에 원문 비밀정보를 쓰지 않는다.** `AuditLog.append` 는 마스킹을
  거친다. 우회 경로를 만들지 않는다.
- **`--allow-egress` 를 기본값으로 만들지 않는다.** 개발 편의 옵션이다.
- 모델 세대에 의존하는 분기를 코드에 두지 않는다. 태그는 설정 값이다.

## 코드 규약

- 문체는 개조식(명사형 종결). `~합니다`, `~됩니다`, `~입니다` 를 쓰지 않는다.
- 주석은 무엇이 아니라 왜를 적는다. 코드가 이미 말하는 것을 반복하지 않는다.
- 예외는 `errors.py` 계층을 쓴다. 사용자가 다음에 무엇을 할지 알 수 있는
  메시지를 담는다.
- 새 모듈을 만들기 전에 기존 계층에 들어갈 자리가 없는지 먼저 본다.

## 산출물

- 색인은 `var/index/`, 감사 로그는 `var/audit/` 에 넣는다. gitignore 처리돼 있다.
- 저장소 루트에 결과 파일을 흩어 놓지 않는다.

## 안전 기준

- 기본 작업 범위는 이 저장소의 체크아웃 루트다. 저장소 밖 경로는 사용자가
  명시적으로 범위를 넓힌 경우에만 변경한다.
- 키, 토큰, 비밀번호, 쿠키를 저장소에 기록하거나 출력하지 않는다.
- 삭제, 덮어쓰기, 강제 푸시 전 정확한 대상과 복구 방법을 확인한다.
- 사용자가 요청하지 않은 커밋·푸시·브랜치 삭제는 하지 않는다.
