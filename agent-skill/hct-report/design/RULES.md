# RULES — 규칙과 그것을 잡는 검사기

**강제**는 검사기가 실패로 잡는다 — 실패가 0 이 아니면 완료가 아니다. **권고**는 검사기가 주의로 알리거나
사람이 눈으로 본다. `hct.py build` 가 목적에 맞는 검사기를 저절로 돌린다.

검사기 — 발표 `scripts/check_live.py`(30항목) · A4 `scripts/check_doc.py`(13항목) · 보드 `scripts/check_board.py`.

## 1. 공통

| 규칙 | 구분 | 검사 |
|---|---|---|
| 색은 토큰만 — hex · `rgb()` · 색 이름을 본문 · 맞춤 CSS 에 새로 쓰지 않는다 | 강제 | 맞춤 CSS 안은 「맞춤 CSS」 실패 · 보드는 「색」 실패 · 덱과 A4 본문은 검사기가 주의로 내지만 `hct.py build` 가 실패로 막는다 |
| 문체는 개조식(명사형 종결). `~합니다` · `~됩니다` · `~한다` · `~없다` 금지. 발표자 노트만 `~한다` | 강제 | 세 검사기 「문체」 |
| 로고 · 회사명 자리가 채워져 있다 — 견본의 「COMPANY NAME」이 남으면 안 된다 | 강제 | 「브랜드 자리」 |
| 스타일 · 본문 글꼴(Pretendard)이 실제로 붙었다 | 강제 | 「스타일」 · 「본문 폰트」 |
| 견본 수치 · 부서명 · 문구를 실제 내용으로 바꿨다 | 강제(사람) | 검사기가 다 잡지 못한다 — 직접 확인 |
| 자료 없는 수치를 지어내지 않는다 — 「확인 필요」로 둔다 | 강제(사람) | — |
| 상태를 색만으로 말하지 않는다 — 칩 글자와 함께 | 권고 | — |

### Word(docx) 판 — `hct.py build --formats docx` 가 HTML 에서 뽑고 `check_docx.py` 가 본다

| 규칙 | 구분 | 검사 |
|---|---|---|
| Word 는 HTML 원본에서만 뽑는다 — `.docx` 를 손으로 짜거나 다른 Word 도구로 만들지 않는다 | 강제 | 사람 |
| HTML 의 글자가 Word 에 하나도 빠지지 않는다 | 강제 | 「HTML 글자 … 모두 Word 에 있음」 |
| 장 · 절 제목은 Word 제목 1 · 제목 2 스타일 — 수가 HTML 과 같다 | 강제 | 「제목 수 일치」 |
| 글꼴은 양식의 `font.body.word` · `font.heading.word` 만(기본 양식 「바탕」 · 「맑은 고딕」) | 강제 | 「글꼴」 |
| 여백이 양식과 같다 | 강제 | 「여백」 |
| 색은 `blue-report.css` 토큰만 (글자 · 음영 · 테두리) | 강제 | 「색 … 모두 토큰」 |
| 양식 `type.small`(기본 9pt) 미만 글자 없음 — 본문 10.5pt, 머리말 · 꼬리말 · 칩 9pt | 강제 | 「…pt 미만 글자」 |
| 머리글 로고 · 문서번호, 바닥글 쪽번호 필드 | 강제 | 「머리글 로고」 · 「바닥글 쪽번호」 |
| 쪽수가 HTML 과 같다 (LibreOffice 렌더 기준 — Word 와 줄바꿈이 조금 다를 수 있다) | 권고 | 「쪽수」 주의 |
| `COMPONENTS.md` 「A4 문서 부품」표에 없는 부품을 쓰지 않는다 — Word 에서 일반 문단으로 떨어진다 | 권고 | build 「주의 모르는 부품」 |

## 5. 형식

| 규칙 | 구분 |
|---|---|
| 내용은 한 곳에만 쓴다 — 형식마다 따로 쓰지 않는다. 형식은 `hct.py build --formats` 로 그 한 곳에서 뽑는다 | 강제 |
| `formats` 에서 「없음」인 조합은 만들지 않는다 — 대안을 말하고 사용자의 선택을 받는다 | 강제 |
| 「제한」 형식은 그 제한을 결과 보고에 적는다(예: PPT 본문은 그림) | 강제 |
| Word 를 넘기면 「Word 에서 고친 내용은 HTML · PDF 원본에 안 돌아간다」를 알린다 — 다시 뽑을 문서면 HTML 을 고친다 | 강제 |
