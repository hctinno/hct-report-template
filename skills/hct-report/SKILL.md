# HCT 회사 보고서

보고서 요청을 받으면 ① 목적과 받을 형식을 정하고 ② 그 조합의 회사 템플릿으로 ③ 내용을 한 번만 써서
④ 요청한 형식들로 만들고 ⑤ 회사 규칙 검사를 통과시킨 뒤 넘긴다. 디자인을 새로 짓지 않는다 — 이 스킬의
로고 · 색 · 글꼴 · 틀 · 부품 · 규칙만 쓴다.

## 0. 경로 규칙

- `<SKILL>` 은 이 `SKILL.md` 가 있는 폴더다(예: `~/.agents/skills/hct-report`). 스킬 파일은 고치지 않는다.
- 명령은 **사용자의 작업 폴더**에서 `python3 <SKILL>/scripts/hct.py …` 로 부른다. Windows 는 `python`.
- 원본과 산출물은 작업 폴더의 `decks-out/` 에 둔다. 브랜드(로고 · 회사명)는 스킬 안 `brand/hct/` 를 저절로 쓴다.

## 1. 순서

1. **목적 · 형식 정하기.** `python3 <SKILL>/scripts/hct.py formats` 로 지금 만들 수 있는 조합을 본다.
   요청에서 목적과 형식이 분명하면 바로 2로 간다. 아니면 **한 번에 하나만** 묻되 추천안을 붙인다 —
   예) "경영회의에서 설명할 자료면 발표 보고(HTML 덱, 필요하면 PPT도)를, 결재 올릴 문서면 문서 보고(PDF, 고쳐 쓸 거면 Word도)를 권합니다."
   | 목적 | 언제 |
   |---|---|
   | `present` 발표 보고 | 말로 설명 — 월간 · 주간 · 경영진 · 제안 · 교육 · 프로젝트 보고 (HTML 덱 · PDF · PPT) |
   | `document` 문서 보고 | 읽고 결재 — 사내 보고서 · 회의록 · 규정 · 매뉴얼 · 공지 (PDF · HTML · **Word**) |

   같은 「월간 보고」라도 **회의에서 띄워 설명하면 `present`, 결재 · 배포용 문서이거나 Word 를 원하면 `document`(`--kind report`)**
   다. 받을 형식이 목적을 가른다 — Word 는 `document` 에만, PPT 는 `present` 에만 있다.
   | `board` 현황 관리 | 고쳐 가며 보는 화면 — 과제 현황판 · 칸반 · 점검표 |
   | `external` 대외 제출 | 고객 · 기관 제출 — FCC/KC 인증 분석 보고서 |
   | `web` 웹 게시 | 소개 · 공지 페이지 — **아직 없음** |
2. **없는 형식이면 만들지 않는다.** `formats` 에서 「없음」인 조합(예: 발표 보고 Word · 현황판 Excel)을 요청받으면,
   그 사실과 대안(「문서 보고로 만들면 Word 로 드릴 수 있습니다」)을 말하고 사용자의 선택을 받는다. 다른 도구(일반
   Word · PPT 스킬 등)로 비슷하게 지어내지 않는다 — 회사 양식이 빠진다.
   「제한」인 조합은 만들되 그 제한을 결과 보고에 적는다.
3. **뼈대 만들기.** `python3 <SKILL>/scripts/hct.py new <목적> decks-out/<보고서이름> [--kind <종류>]`
4. **내용 쓰기.** 뼈대의 견본 문구 · 수치 · 부서명을 **전부** 실제 내용으로 바꾼다. 견본은 자리표시자가 아니라
   사용법 예시다 — 남기면 남의 숫자가 그대로 나간다. 자료가 없는 수치는 지어내지 말고 「확인 필요」로 둔다.
   - `present`: `<SKILL>/DESIGN.md`(본문 스타일 한 장)를 **처음부터 끝까지** 읽고 `deck.yaml` · `slides.html` 을 쓴다.
     장마다 내용 모양을 정해 `<SKILL>/LAYOUTS.md`(짜임 카드 12종)에서 짜임을, `<SKILL>/COMPONENTS.md`(부품 카드 24종)에서
     부품을 고른다. 카드의 복사용 HTML 을 가져와 클래스 · 속성 이름은 그대로 두고 내용만 바꾼다.
     - 시각 스타일은 `deck.yaml` 의 `style: c`(혼합형 · 권장). `new` 가 넣어 둔다 — 지우지 않는다.
     - **보고 요지**(`front: [gist]`)는 흐름형 `bl-gist--flow` 그대로 — 결론 한 줄(`bl-gist-h`) · 현황 → 실행 → 판정
       3단 큰 수치(`bl-gist-steps`) · 결정 요청 옅은 띠(`bl-gist-ask`). 좌우 반반형(`bl-gist-l` · `bl-gist-r`)으로
       바꾸지 않는다 — 무거운 요청 상자가 결론보다 먼저 보이고 근거 수치가 문장에 묻힌다.
     - **결정 요청**은 `COMPONENTS.md` 「결정 요청 판」의 복사용 HTML 구조 그대로 — 칸을 더하지 않는다.
       `bl-decide-msg` 에 **무엇을**(굵게 한 줄)과 **언제까지 · 안 하면**(한 문장 — 예: 「11월 27일 결정 시 1월 가동 ·
       지연 시 2월로 밀림」)을 쓰고, `bl-decide-card` 는 요청 1건에 1장(도장 하나). 기한 · 영향을 모르면 그 문장에
       「확인 필요」라고 쓴다 — 무엇을 · 언제까지 · 안 하면을 따로 카드로 늘어놓지 않는다. 요청 4건 이상이면 장을 나눈다.
   - `document` · `external` · `board`: 복사된 HTML 의 주석(「교체:」)을 따라 내용만 바꾼다. 틀(머리말 · 꼬리말 ·
     로고 자리 · 결재란 구조)은 건드리지 않는다.
     여백 · 글자 크기 · 색 역할 · 머리말 · 꼬리말 · 표 · 결재란 모양은 **양식 정의**(`<SKILL>/forms/<id>.json`)가 정한다 —
     HTML · PDF · Word 가 같은 파일을 읽는다. 기본은 **회사 공식 문서 양식 `hct-official`**(규정 · 강령 원본을 잰 것 — 명조 본문,
     왼쪽 문서명 · 오른쪽 로고 · 두 줄 선 머리말, Ⅰ·Ⅱ 번호 칸 장 제목, 「회사명 · 문서명 / 쪽」 꼬리말, 쪽은 저절로 나뉜다). 장 제목은 `1. 요약` 처럼
     숫자로 쓴다 — 양식이 Ⅰ 로 바꾼다. 규정 · 매뉴얼처럼 표지가 필요하면 `.bd-doc` 에 `data-doc-cover="yes"`.
     **A4 짜임 · 부품 쓰임의 기준 견본은 종합 계획서 `--kind plan`(20쪽)이다** — 결론 먼저 · 시작선 하나 · 표 합계 맞춤 ·
     제목은 쪽 끝에 남기지 않는다(`design/RULES.md` 「3」).
     예전 블루 리포트 모양(프리텐다드 · 쪽번호)이 필요하면 `data-form="hct-standard"`. 문서 안에 양식 값을 `style` 로 덮어쓰지
     않고, 양식 파일을 고치지도 않는다(`hct.py form` 으로 볼 수만 있다). 양식이 문서에 맞지 않으면 사용자에게 알린다.
     문서명 · 문서번호는 `.bd-doc` 의 `data-doc-title` · `data-doc-no` 에 쓴다. 번호 규칙을 모르면 견본 번호를 남기거나
     지어내지 말고 `data-doc-no="문서번호 확인 필요"` 로 둔다. 결재란(`.bd-sign`)은 결재 문서일 때만 남긴다.
   - **Word 가 필요해도 HTML 원본에 쓴다.** `--formats docx` 가 그 HTML 에서 Word 를 뽑는다(글자 · 표 · 목록 전부
     Word 에서 고칠 수 있다). `.docx` 를 직접 만들거나 일반 Word 도구로 다시 짜지 않는다. 부품은 `design/COMPONENTS.md`
     「A4 문서 부품」표의 `bd-*` 만 쓴다 — 표에 없는 부품은 Word 에서 일반 문단으로 떨어진다(build 가 「주의」로 알린다).
   - 모든 목적: `design/RULES.md` 를 지킨다.
5. **만들고 검사.** `python3 <SKILL>/scripts/hct.py build decks-out/<보고서이름> --formats <형식들>`
   — 형식들을 만들고 검사기를 돌린다. 산출물은 원본 폴더 옆에 `decks-out/<보고서이름>.html · .pdf · .pptx · .docx` 로
   생긴다(HTML 은 다른 형식의 원본이라 요청하지 않아도 남는다). **검사 실패가 0 이 될 때까지 원본을 고치고 다시 build 한다.**
   주의는 완료를 막지 않지만 원인을 읽고, 고칠 수 있으면 고친다(글 · 표뿐인 장 · 움직임 과다 등).
6. **보고.** 아래 「3. 넘길 때」대로.

## 2. 꼭 지킬 것 (요약 — 전부는 `design/RULES.md`)

- 색 · 글꼴 · 크기는 토큰(`--br-*` · `--bl-*`)만. hex · `rgb()` · 다른 글꼴을 새로 쓰지 않는다.
- 문체는 개조식(명사형 종결). 지면에 `~합니다` · `~한다` · `~없다` 를 쓰지 않는다. 발표자 노트만 `~한다`.
- 발표 보고 제목은 주장 한 문장 — 「주장 — `<em>`핵심구`</em>`」. 한 장 한 주장, 주인공 도식 하나.
- 파이 차트 금지(도넛만, `scripts/donut.py`). 데이터 마크는 배경 대비 2:1 이상.
- 글자 하한 — 발표 24px(1.0rem) · A4 10.5pt · 보드 12.5px. 넘치면 줄이지 말고 장 · 쪽을 나눈다.
- 머리띠 · 꼬리띠 · 쪽번호 · 로고 · 워터마크 · 표지 · 목차 · 간지는 빌드가 단다 — 직접 쓰지 않는다.
- 근거가 있는 수치에는 출처 칩 — `<button type="button" class="bl-ev" data-ev="E1">출처</button>` + `evidence.json`.

## 3. 넘길 때

한국어로 짧게. 다음을 반드시 넣는다.
- 산출물 경로(형식별)와, 「제한」 형식이면 그 제한(예: PPT 본문 도식은 그림)
- Word 를 넘기면: 내용을 Word 에서 고치면 HTML · PDF 원본과 달라진다는 점(다음에 다시 뽑을 거면 HTML 원본을 고친다),
  Pretendard 가 없는 PC 에서는 다른 글꼴로 보인다는 점
- 검사 결과 — 통과 · 주의 · 실패 수. 검사를 안 돌렸으면 안 돌렸다고 쓴다
- 바꾸지 못했거나 「확인 필요」로 둔 내용
- HTML 발표 덱이면 조작법:

| 키 | 하는 일 |
|---|---|
| `F5` / `Shift+F5` | 처음부터 발표 / 이 장부터 발표(다시 누르면 끝) |
| `Alt+F5` | 발표자 보기 — 대본 · 타이머 · 다음 장 |
| `→` `Space` / `←` | 다음(단계 먼저) / 이전 |
| 숫자 + `Enter` | 그 쪽으로 (`a` 를 먼저 누르면 부록 쪽) |
| `M` · `X` · `V` | 이 장 노트 · 단계 모두 펼치기 · 가로 보기 |
| `P` · `L` · `B` | 펜 · 레이저 · 검은 화면 |
| `F1` · `?` | 단축키 전부 |

## 5. 준비물

- Python 3.9+ · Node.js 18+(PPTX · Word 만들 때). 첫 실행에 Chromium(약 150MB)과 npm 패키지를 스스로 받는다.
  사내망에서 막히면 사용자에게 알리고 멈춘다. 설치를 막으려면 환경변수 `BLUE_REPORT_NO_INSTALL=1`.
- 이 스킬은 `hctinno/hct-report-template` 저장소에서 묶은 것이다(저장소의 build_hct_skill.py).
  고칠 일이 생기면 설치본이 아니라 저장소를 고친다.
