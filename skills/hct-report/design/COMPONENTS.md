# COMPONENTS — 목적별 부품

부품은 **내용의 모양**으로 고른다(흐름 · 일정 · 비교 · 구성 · 수치 · 구조 · 화면 · 사례). 이름을 외우지 말고,
내용을 먼저 보고 아래에서 표현을 고른 뒤 견본 마크업을 가져와 고친다. 칸 수 · 문구는 내용에 맞게 바꾼다.

형식 열 — **글자**: 그 형식에서 편집 가능한 글자로 들어간다 · **그림**: 고해상도 그림으로 들어간다 · **—**: 해당 없음.

## 1. 발표 보고 (`present`) — 라이브 덱

### 장의 뼈대 — 모든 본문 장
| 부품 | 마크업 | 쓰는 법 | PPTX |
|---|---|---|---|
| 제목 | `h2.bl-title` + `<em>` | 주장 한 문장. 핵심구를 `<em>`(형광 밴드)로 | 글자 |
| 리드 | `p.bl-lede` + `<strong>` | 기준일 · 범위 · 굵은 결론 한 줄 | 글자 |
| 본문 칸 세로 가운데 | `.bl-mid` | 주인공 덩어리에 | 그림 |
| 출처 | `p.bl-src` · `button.bl-ev` | 수치의 근거. 칩은 `evidence.json` 과 짝 | 그림 |
| 장 결론 | 조립 목록 `takeaway` | 장(章)마다 한 번. 본문 장마다 붙이지 않는다 | 그림 |
| 발표자 노트 | `data-notes` | `~한다` 형 · `[클릭]` 수 = 단계 수 | 글자(노트 창) |

### 짜임과 부품 — 카드에서 고른다
- **짜임**(장 하나를 어떻게 나누나): `<SKILL>/LAYOUTS.md` — 큰 금액 · 추세 + 구성 · 규칙 전후 · 구조 · 경로 · 1:1 비교 ·
  분류 · 계획 · 화면 · 단계별 수치 · 요약 지도 · 점검 카드.
- **부품**(장 안에 넣는 것): `<SKILL>/COMPONENTS.md` — 수치 타일 · 가로 막대 · 도넛 · 누적 막대 · 계단 · 히어로 · 쉐브론 ·
  간트 · 연표 · 조직도 · 역할 매트릭스 · 좌우 대비 · **결정 요청 판** · 파이프라인 · 색띠 카드 · 탭 · 결론 줄 · 출처 칩 등 20종.
- 두 문서는 저장소 원본(`live-catalog.html` · `blue-live.css` · `examples/layouts`)에서 **생성**된다 — 이 색인보다 앞선다.
- 카드에 없는 표현은 `assets/live-catalog.html` · `assets/live-patterns.html` 의 장을 참고해 `<style data-own>` 으로 짠다.

### 정해진 장 두 가지
| 장 | 반드시 이 모양 | 견본 |
|---|---|---|
| 보고 요지(`front: [gist]`) | 흐름형 `bl-gist--flow` — 결론 한 줄 · 현황 → 실행 → 판정 3단 큰 수치 · 결정 요청 옅은 띠 | `examples/standard` 장 `gist` |
| 결정 요청 | `bl-decide` 구조 그대로 — 요청 사항 칸에 무엇을 + 「언제까지 · 안 하면」 한 문장, 카드는 요청 1건에 1장 · 도장 하나. 칸을 더하지 않음 · 4건 이상이면 장을 나눔 | `COMPONENTS.md` 「결정 요청 판」 |

### 틀 — 빌드가 만든다(직접 쓰지 않음)
표지 · 목차 · 장 간지 · 마무리 · 부록 간지 · 머리띠 · 꼬리띠 · 쪽번호 · 로고 · 워터마크 · 진행선 · 발표 엔진.
시각 스타일은 `deck.yaml` 의 `style: c`(혼합형 · 권장) · `a`(프레임형). 본문은 같고 보이는 규칙만 바뀐다.
PPTX 로 낼 때 이것들은 PowerPoint 글자로 들어간다(디자인은 HTML 과 일부 다름 — 다음 판에서 맞춘다).

## 2. 문서 보고 (`document`) · 대외 제출 (`external`) — A4

| 부품 | 마크업 | 쓰는 법 | Word(docx) 에서 |
|---|---|---|---|
| 머리말 · 꼬리말 | 틀 (`.bd-head` · `.bd-foot`) | 손대지 않는다 | 머리글(로고 그림 · 문서번호) · 바닥글(회사명 · 문서명 · 쪽번호 필드 n / 전체) |
| 표제 | `h1.bd-title` · `p.bd-subtitle` | 첫 쪽에 한 번. 부제는 결론 한 줄 | 스타일 「제목」 · 「부제」 |
| 문서 정보 | `.bd-meta` (라벨 `.bd-meta-k` + 값) | 일자 · 대상 · 부서 · 작성자 · 기준 기간 · 데이터 | 4칸 표 (라벨 칸 음영) |
| 장 · 절 제목 | `h2.bd-h1` · `h3.bd-h2` | 번호를 손으로 매긴다(1. · 1.1) | 스타일 「제목 1」 · 「제목 2」 — 탐색 창 · 자동 목차에 잡힌다 |
| 본문 · 목록 | `p.bd-p` · `ul.bd-list` · `.bd-list--legal`(규정의 호) | 개조식 | 본문 · 글머리 목록 · 규정 호는 (1) (2) **글자 번호**(개정해도 안 바뀐다) |
| 표 | `table.bd-table` · `.bd-table--grid` · 숫자 칸 `td.num` | 머리글에 단위. 숫자는 오른쪽 정렬 | 표 — 머리글 행은 쪽이 넘어가면 반복 |
| 강조 · 상태 | `.bd-key` · `.bd-chip` · `--warn` · `--late` | 상태는 칩 글자로 | 문자 스타일 「HCT 강조어」 · 「HCT 칩」 · 「HCT 칩 주의」 · 「HCT 칩 위험」 |
| 강조 상자 | `.bd-callout` · `--info`(요청) · `--danger`(리스크) · 라벨 `.bd-callout-k` | 쪽마다 하나 안팎 | 테두리 · 음영 문단 (모서리는 각지게) |
| 절차 | `.bd-steps` > `.bd-step` > `.bd-step-t` | 매뉴얼 · 공지 · 일정 | Word 자동 번호 ①②③ — 끼워 넣으면 다시 매겨진다 |
| 목차 | `.bd-toc` | 매뉴얼 | 점선 탭 목차 (쪽번호는 HTML 처럼 손으로) |
| 그림 | `.bd-figure` > `img` + `figcaption` | 매뉴얼 화면 캡처 | 1칸 표 (그림 + 캡션) |
| 결재란 | `.bd-sign` | 마지막 쪽 꼬리말 바로 위 | 결재 표 — 본문 끝에 붙는다(쪽 바닥 고정은 아님) |
| 수치 표 · 가로 막대 | `.bd-kpis` · `.bd-bars` (공용 부품 — 1.58, 옛 `x-` 이름도 Word 변환은 읽는다) | 사내 보고서 1 · 2쪽 | 표 짜임으로 그린다. 나쁜 증감 `b.is-bad`, 주인공 막대 `.is-main`. 막대 너비는 값을 고쳐도 저절로 안 바뀐다 |

부품의 **값과 짜임**(여백 · 크기 · 색 역할 · 머리말 짜임과 띠 · 장 제목 막대/상자 · 장 번호 Ⅰ · 글머리 표시 · 호 번호 ①② · 표지 ·
쪽 흘림)은 양식 정의 `forms/<id>.json` 에서 온다. 기본 양식 `hct-official` 에서 `h2.bd-h1` 은 번호 칸 상자, 목차는 쪽번호 없이 나온다 —
`forms/README.md` 「항목」 표. 쪽 나눔은 HTML 의 쪽(`.bd-page`)과 같은 자리다(양식 `word.pageBreak`). 이 표에 없는 부품(새 `x-*` 등)은 Word 에서 일반 문단으로
떨어진다 — build 가 「주의 모르는 부품」으로 알린다. 그 문서를 Word 로도 낼 거면 표의 부품으로 바꾼다.

## 3. 현황 관리 (`board`) — 웹 보드

| 종류 | 기준 | 부품 |
|---|---|---|
| 관리보드 `manage` | HCT 웹 디자인 템플릿 v2.1.0 — 앱 셸(사이드바 · 상단바) · `hct-*` 부품 · 상태 색 이름 | `assets/hct-web.css`(생성) · `assets/hct-board.css` — 견본의 부품을 그대로 쓴다 |
| 보관 보드 `task` · `exec` · `team` · `gap` | 옛 블루 리포트 웹 보드 | `.bw-*` (`assets/blue-web.css`) |

보드는 화면에서 상태를 바꾸는 물건이다 — PDF · PPTX 대상이 아니다. 실제로 동작하는 사내 웹 앱은 보드 견본이 아니라
웹 디자인 템플릿(React + Tailwind)을 직접 쓴다.
