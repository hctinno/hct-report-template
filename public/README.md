# 공개본 빌드 재료

이 폴더는 **비공개 저장소에서만 쓴다.** 공개본(`hctinno/blue-report`)을 만들 때
`scripts/build_public_release.py` 가 여기 있는 것을 읽는다. 공개본 자체에는
이 폴더가 들어가지 않는다.

## 왜 있는가

공개본은 비공개본에서 템플릿·스크립트·문서만 뽑아 낸 것이다. 실명·조직명·사내
계획·구 계정 핸들을 걷어내고, 파일 이름에 박힌 사내 제품명을 바꾸고, 공개용 문서
세 벌을 덮어쓴다.

손으로 하면 열댓 단계다. 한 번은 해냈지만 판올림마다 되풀이하면 어느 회차에서
반드시 하나를 빠뜨린다 — 실제로 스크립트로 옮기는 과정에서 **치환 규칙 하나가
빗나가 계정 복구 이력이 공개본에 실릴 뻔했다.** 공개 push 는 되돌릴 수 없다.

## 무엇이 들어 있나

| 자리 | 내용 |
|---|---|
| `config.py` | 제외·이름변경·덮어쓰기 목록과 치환표 여섯 벌, 유출 검사 패턴 |
| `overlay/` | 공개본 전용으로 손수 쓴 파일. 그대로 덮어쓴다 |
| `brand-sample/` | 중립 견본 브랜드. 공개본의 `brand/sample/` 로 들어간다 |
| `VERSION` | 공개본 판번호. 비공개본과 따로 센다 |

## 판올림 절차

1. `public/VERSION` 을 올린다
2. `public/overlay/CHANGELOG.md` 에 그 판번호로 항목을 적는다
   (없으면 스크립트가 거부한다 — 받는 사람이 자기 판을 확인할 곳이 없어지므로)
3. 빌드하고 결과를 본다

```bash
python3 scripts/build_public_release.py --out /tmp/pub      # 만들고 검증만
python3 scripts/build_public_release.py --out /tmp/pub --commit
python3 scripts/build_public_release.py --out /tmp/pub --commit --push
```

`--push` 는 `hctinno/blue-report` 의 `main` 을 통째로 덮어쓴다. 공개본은 이
스크립트가 유일한 작성자이므로 그래도 된다 — 공개본에서 직접 고친 것이 있다면
먼저 비공개본으로 옮겨 온다.

## 규칙을 고칠 때

스크립트가 아니라 `config.py` 를 고친다. 스크립트는 순서만 안다.

치환은 **긴 문자열부터** 적용한다. 짧은 것을 먼저 바꾸면 긴 문자열이 조각나
남는다 — 「AX전략파트」를 먼저 바꾸면 「AX전략파트 주간보고」라는 덱 제목이 깨진다.
표의 순서가 곧 우선순위다.

`DENY` 는 치환이 실패해도 걸러 내는 마지막 관문이다. 치환 규칙을 새로 넣었으면
그 규칙이 잡아야 할 문자열을 `DENY` 에도 넣는다. 규칙은 원문이 한 글자만 바뀌어도
빗나가지만 `DENY` 는 결과를 보므로 빗나가지 않는다.

`EXPECT` 는 반대다. 0 이면 실패한다 — 브랜드가 통째로 빠진 빌드를 막는다.

## 손대지 않는 것

`brand/hct/` 와 `dist/` 는 치환 대상에서 뺀다.

`brand/hct/` 는 실제 브랜드 설정이라 바꿀 것이 없다. 잘못 건드리면 `brand.json`
이 없는 로고 파일을 가리켜 빌드가 죽는다.

`dist/` 는 로고가 base64 로 박혀 있어 짧은 문자열이 그림 데이터 한가운데에서도
걸린다 — 실제로 `HCTyVEpv` 가 있다. 대신 8단계에서 `assets/` 로부터 다시 만든다.

`overlay/` 도 치환하지 않는다. 이미 공개본 기준으로 쓴 글이라 한 번 더 먹이면
멀쩡한 문장이 뒤집힌다 — 실제로 「`brand/hct` 가 기본이고」가 「`brand/sample` 가
기본이고」로 뒤집혔다.
